## 1. 自鯖Worker とは

Voiloid の音声は **Worker** が作ります。Worker には 2 種類あります。

| 種類 | 動かす人 | 使われる場所 |
|---|---|---|
| 公式Worker | 運営 | すべてのサーバー（運営が担当を限定している場合を除く） |
| 自鯖Worker | あなた | あなたが接続したサーバーだけ |

自鯖Worker を使うと、次のようなことができます。

- 公式Worker に無いエンジン（AivisSpeech・COEIROINK など）や、自分で入れたモデルの声を使う
- 混雑の影響を受けずに、自分のサーバーの読み上げを速くする

**注意**: 自鯖Worker で音声を作るとき、読み上げるメッセージの文章があなたの PC に送られます。サーバーに「共有」すると、そのサーバーのメンバー全員の発言があなたの PC で処理されます。

## 2. 用意するもの

1. **Docker**（Windows・Mac は Docker Desktop、Linux は Docker Engine）
2. **音声合成ソフト**を同じ PC で起動しておく

| エンジン | 起動するもの | 使うポート |
|---|---|---|
| VOICEVOX | VOICEVOX（アプリ、またはエンジン） | 50021 |
| AivisSpeech | AivisSpeech（アプリ、またはエンジン） | 10101 |
| COEIROINK | COEIROINK | 50032 |

3. 読み上げに使う間、PC を起動したままにしておく

1 人が登録できる自鯖Worker の数には上限があります（既定は 10 台）。

---

## 3. 登録して起動する

1. Web コンソールの「Workers」→「Workerを追加」を開く
2. **基本情報**: Worker の名前を付ける（例: `gaming-pc`）
3. **Engine**: この PC で動かすエンジンを選ぶ（1 つ以上）
4. **セットアップ**: 「Workerを作成」を押すと、**接続トークン** と起動の方法が表示されます
   - トークンは **この画面でしか表示されません**。他人に見せないでください
   - 起動の方法は 3 つから選べます
     - **Docker Compose**: 表示された内容を `compose.yaml` という名前で保存し、そのフォルダで `docker compose up -d` を実行します（おすすめ。PC を再起動しても自動で起動します）
     - **Docker**: 表示されたコマンドをそのまま実行します
     - **環境変数**: 既存の環境に組み込む場合に使います
5. 起動したら「起動したので接続を確認」を押す
6. 「Workerが接続されました」と表示されれば完了です

Worker は、同じ PC の音声合成ソフトに `host.docker.internal` という名前で接続します。音声合成ソフトを先に起動しておいてください。

## 4. サーバーに接続する

登録しただけでは、どのサーバーでも使われません。Worker の詳細ページ（「Workers」で Worker を選ぶ）の **接続するサーバー** で、使うサーバーを選びます。

| 接続のしかた | 使われる読み上げ | 条件 |
|---|---|---|
| 接続しない | 使われません | — |
| サーバーで共有 | そのサーバーの **全員** の読み上げ | そのサーバーの管理権限が必要 |
| 自分専用 | そのサーバーでの **あなたの発言** の読み上げだけ | 参加しているだけのサーバーでも可 |

- 「サーバーで共有」した Worker が実際に使われるかは、サーバーの「Worker」タブの設定（自動・公式のみ・自鯖優先・Worker を指定）で決まります（[利用者ガイド 5-5](user-guide.md#5-5-worker音声を作る場所)）
- 「自分専用」で接続した Worker は、あなたの発言を読むときに最優先で使われます。マイボイスに、この Worker のエンジンの声を選んでおくと、そのサーバーでもマイボイスで読まれます

## 5. 管理する（名前・トークン・削除）

Worker の詳細ページでできること:

| 操作 | 説明 |
|---|---|
| 編集 | Worker の名前を変えます |
| 同時処理の数 | この Worker が同時に処理する数です（1〜64）。空なら Worker 側の設定（環境変数 `MAX_CONCURRENCY`、既定 2）を使います。PC の負荷を抑えたいときは小さく、余裕があれば大きくします。古いバージョンの Worker は `MAX_CONCURRENCY` より大きくできないので、画面に案内が出たら Worker を最新のイメージで起動し直してください |
| トークンを再発行 | 新しいトークンを発行します。古いトークンはすぐに使えなくなり、接続中の Worker は切断されます。新しいトークンで Worker を起動し直してください |
| 削除 | Worker を削除します。トークンも使えなくなります |

**トークンが漏れたかもしれないときは、すぐに「トークンを再発行」を押してください。** トークンを持っている人は、あなたの Worker として接続できてしまいます。

詳細ページでは、Worker の状態（オンライン・オフラインなど）、対応エンジンの状態、実行中の処理の数・レイテンシも確認できます。

## 6. 困ったとき

**「Workerの接続を待っています…」のまま進まない**
- Worker のコンテナが起動しているか確認します: `docker ps`
- ログを確認します: `docker compose logs -f`（Docker の場合は `docker logs -f voiloid-worker`）
  - `connected to the gateway` と出ていれば接続できています
  - `reconnecting` を繰り返す場合は、トークンが間違っているか、トークンを再発行・Worker を削除した可能性があります
- イメージの取得（`docker pull`）に失敗する場合は、運営にお問い合わせください

**状態が「オフライン」になる**
PC がスリープした、Docker が止まった、ネットワークが切れた、などが考えられます。Worker は自動で接続し直します。

**エンジンが「Unhealthy」になる**
- 音声合成ソフトが起動しているか確認してください
- ポート番号（VOICEVOX は 50021 など）を変えている場合は、`VOICEVOX_URL` などの環境変数を合わせてください
- 初回の起動直後は、モデルの読み込みに 1〜2 分かかることがあります

**声の一覧に自分の Worker の声が出ない**
Worker がオンラインで、エンジンが「Healthy」である必要があります。サーバーの「Voice」タブでそのエンジンがオフになっていると、そのサーバーでは使えません。
